# Triage（Issue 分诊）

默认使用简体中文与用户沟通。分诊建议、问题、总结和交接说明都用中文；issue 标签、命令、文件名、代码标识符保持原文。

在项目 issue tracker（问题跟踪器）上，通过一组小型 triage roles（分诊角色）状态机推进 issue。

分诊期间发布到 issue tracker 的每条评论或 issue **必须**以下列免责声明开头：

```
> *This was generated by AI during triage.*
```

## 参考文档

- [AGENT-BRIEF.md](AGENT-BRIEF.md)：如何编写可长期使用的 agent brief（代理任务简报）
- [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)：`.out-of-scope/` 知识库如何工作

## 角色

两个**类别**角色：

- `bug`：某些东西坏了
- `enhancement`：新功能或改进

五个**状态**角色：

- `needs-triage`：需要维护者评估
- `needs-info`：等待报告者提供更多信息
- `ready-for-agent`：规格完整，适合交给 AFK agent
- `ready-for-human`：需要人工实现
- `wontfix`：不会处理

每个已分诊 issue 都应该恰好拥有一个类别角色和一个状态角色。如果状态角色冲突，先标记问题并询问维护者，再做其他动作。

这些是标准角色名；issue tracker 中实际使用的 label 字符串可能不同。映射关系应已提供；如果没有，运行 `/setup-matt-pocock-skills`。

状态转换：无标签 issue 通常先进入 `needs-triage`；然后转到 `needs-info`、`ready-for-agent`、`ready-for-human` 或 `wontfix`。`needs-info` 在报告者回复后回到 `needs-triage`。维护者可以随时覆盖状态；遇到异常转换时先标记并询问，再继续。

## 调用方式

维护者调用 `/triage` 并用自然语言说明需求。解释请求并执行。示例：

- “给我看看哪些需要我关注”
- “看一下 #42”
- “把 #42 移到 ready-for-agent”
- “哪些已经可以让 agent 接手？”

## 展示需要关注的内容

查询 issue tracker，并按从旧到新展示三类：

1. **无标签**：从未分诊。
2. **`needs-triage`**：正在评估。
3. **`needs-info` 且报告者在上次分诊备注后有活动**：需要重新评估。

展示数量和每个 issue 的一行摘要，让维护者选择。

## 分诊某个具体 issue

1. **收集上下文。** 阅读完整 issue，包括正文、评论、标签、报告者和日期。解析之前的分诊备注，避免重复询问已解决问题。使用项目领域术语表探索代码库，并尊重相关区域的 ADR。阅读 `.out-of-scope/*.md`，找出是否有类似问题曾被拒绝。

2. **给出建议。** 向维护者说明你推荐的类别和状态，并给出理由，再附上与该 issue 相关的代码库简短摘要。等待指示。

3. **复现，仅限 bug。** 在任何追问前先尝试复现：阅读报告者步骤、追踪相关代码、运行测试或命令。报告结果：成功复现并附代码路径、复现失败，或信息不足。信息不足是强烈的 `needs-info` 信号。确认复现会让 agent brief 更可靠。

4. **追问，如有需要。** 如果 issue 需要补充细节，运行 `/grill-with-docs` 会话。

5. **应用结果：**
   - `ready-for-agent`：发布 agent brief 评论（[AGENT-BRIEF.md](AGENT-BRIEF.md)）。
   - `ready-for-human`：使用 agent brief 相同结构，但说明为什么不能委托，例如需要判断、外部访问、设计决策或手动测试。
   - `needs-info`：发布分诊备注，模板见下方。
   - `wontfix`，bug：礼貌解释，然后关闭。
   - `wontfix`，enhancement：写入 `.out-of-scope/`，在评论里链接它，然后关闭（[OUT-OF-SCOPE.md](OUT-OF-SCOPE.md)）。
   - `needs-triage`：应用该角色。如果已有部分进展，可选择评论。

## 快速状态覆盖

如果维护者说“把 #42 移到 ready-for-agent”，信任他们并直接应用角色。先确认你将要做什么，例如角色变更、评论、关闭，然后执行。跳过追问。如果没有追问会话就移动到 `ready-for-agent`，询问是否要写 agent brief。

## Needs-info 模板

```markdown
## Triage Notes（分诊备注）

**目前已确认：**

- 要点 1
- 要点 2

**仍需你提供的信息（@reporter）：**

- 问题 1
- 问题 2
```

把追问期间已经确认的内容全部放到“目前已确认”下面，避免工作丢失。问题必须具体、可执行，不要只写“请提供更多信息”。

## 恢复之前的会话

如果 issue 上已有分诊备注，先阅读它们，检查报告者是否回答了未解决问题，并在继续前展示更新后的情况。不要重复询问已解决问题。
